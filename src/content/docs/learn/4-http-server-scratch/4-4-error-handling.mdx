## What you will learn

Errors reach your server through two channels and you need a net for each. **Synchronous** throws inside a handler are catchable: wrap the handler body in `try/catch`, send a 500, log the stack, keep serving. **Async** failures — a rejected promise, an `error` event on a stream — are invisible to `try/catch`; only `.catch()` (or `async handler` + a `.catch` wrapper) sees them. And the stakes are real: since Node 15 an **unhandled rejection crashes the process by default** — one missing `.catch` in a route takes the whole server down. The demo shows both nets plus the process-level last resort: `process.on('uncaughtException')` fires, but by then the process state is unknown — the handler is for *logging and a clean exit*, not for keeping serving. The error-first callback convention you meet throughout Node's fs/net/crypto (`(err, result) => ...`) is the third net, and 404 vs 500 discipline — unknown route is a client problem, a thrown handler is yours — keeps meaning flowing to clients and stack traces flowing to logs.

<Pitfall title="uncaughtException handlers are for exit, not for heroics">
	<p>
		After an uncaught exception the V8 heap may hold half-finished mutations — state you can no longer reason about. The handler's job: log with the stack, flush logs, `process.exit(1)`, and let the orchestrator (PM2, Docker, Kubernetes) restart a clean process. Serving more requests on a corrupted process risks writing garbage everywhere. `unhandledRejection` carries the same rule — log, then exit deliberately.
	</p>
</Pitfall>

## Two nets and a last resort

Run the demo file for this lesson:

```bash
node code/4-http-server-scratch/4-4-error-handling/demo.js
```

It prints: `[1]` a sync throw caught by `try/catch`, 500 sent, process alive; `[2]` the same async rejection caught by `.catch` (500 sent) — then the *same* rejection with no `.catch` run in a child process: exit 1, process dead, because unhandled rejections crash Node by default; `[3]` an `uncaughtException` in a child: the handler logs, prints its exit rationale, and exits deliberately — the last resort behaving like one.
