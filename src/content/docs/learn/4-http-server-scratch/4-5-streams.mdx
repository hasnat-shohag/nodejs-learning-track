## What you will learn

Everything in Node that moves data is one of four classes. **Readable** produces data (`fs.createReadStream`, `process.stdin`, HTTP request bodies); **Writable** consumes it (`fs.createWriteStream`, `process.stdout`, HTTP responses); **Duplex** does both with *independent* buffers (a TCP socket, a `tls` connection); **Transform** is a stage — in one end, `transform()` fn, out the other (zlib's gzip, crypto ciphers). The API you learn here is the API everywhere: `data`/`end` on the way in, `write()` on the way out, and the two facts people miss. First, `pause()` genuinely stops the flow — no `data` events fire until `resume()`. Second, `write()` returns a **boolean**: `true` means keep pushing, `false` means the internal buffer has passed **highWaterMark** and you should stop and wait for `'drain'`. That boolean is the foundation of the next lesson — backpressure — and it is not optional knowledge for a server dev.

<Pitfall title="Duplex sides are buffered separately — one full does not gate the other">
	<p>
		A Duplex stream has a readable buffer and a writable buffer, sized independently. Writing the write side past its highWaterMark does not pause the read side; the two flows are separate and each carries its own backpressure signal. People assume "the stream is full" — there is no single stream-full; there are two buffers with two write() bools. A proxy that honors write-side backpressure but ignores read-side flow control will still misbehave, in the other direction.
	</p>
</Pitfall>

## Four classes, four runs

Run the demo file for this lesson:

```bash
node code/4-http-server-scratch/4-5-streams/demo.js
```

It prints: `[1]` a Readable paused mid-flow — 50 ms pass with no `data` events, then `resume()` lets the rest through: pause is real; `[2]` a Writable with a 16-byte highWaterMark taking 48 bytes — `write()` returned false 9 times: the bool is the backpressure signal; `[3]` a Duplex whose read side delivered its chunks while the write side took 20 writes — two independent buffers, one object; `[4]` a Transform uppercasing in-flight, next to `createGzip()` — the same class in the wild, 13 bytes in, gzip bytes out.
