## What you will learn

**Backpressure** is the downstream end saying "slow down": the writable's internal buffer has reached **highWaterMark** (>=), `write()` returned `false`, and pushing more data just grows memory. The disciplined response is a two-line loop — on `false`, stop writing and wait for `'drain'`; on `drain`, write again. Memory stays pinned near the highWaterMark no matter how slow the sink or how fast the source. Ignoring the signal is not a style choice: with a 10 ms-per-write sink, the demo's 399 ignored falses left 14 KB (measured by `writableLength`) parked in the buffer — and in a real server that is *one slow client's response* ballooning in RAM, multiplied by every slow client you have. The payoff of understanding the loop is realizing you rarely write it: `pipe()` implements exactly this pause/resume dance between a readable and a writable, and `pipeline()` (stream/promises) does the same with error propagation end-to-end. A file streamed with `pipe` cannot outrun its client — that is not magic, it is the loop you just wrote.

<Pitfall title="pipe() moves data but not errors — pipeline() moves both">
	<p>
		`src.pipe(dest)` forwards data and handles backpressure, but an error in the middle of a pipe chain emits on the failed stream and the *other* streams keep running — half-broken pipes leak. `pipeline(src, transform, dest)` from `node:stream/promises` wires `error` end-to-end, destroys every stream on failure, and returns a promise. In a server, prefer `pipeline` for anything multi-stage: streams that survive a failed request must be destroyed, or they hold file descriptors and memory.
	</p>
</Pitfall>

## Feel the signal, honor it, then delete the loop

Run the demo file for this lesson:

```bash
node code/4-http-server-scratch/4-6-backpressure/demo.js
```

It prints: `[1]` a fast source into a slow sink — 20 writes, 13 returned false: the signal arriving; `[2]` the same pair honoring it — 30 chunks through 3 drain cycles, memory near the highWaterMark instead of near the transfer size; `[3]` the same pair ignoring it — 400 writes, 399 falses ignored, ~14 KB sitting in the sink's buffer; `[4]` `pipe()` moving the same 30 chunks with zero drain code written — the loop, already written for you; `[5]` `pipeline()` with a failing middle stage — the promise rejects and every stage is destroyed, where `pipe` would have leaked them.
