## What you will learn

Strip Express to its bones and two ideas remain. The **router** is a table of `(method, pattern, handler)` rows; matching is a loop over the table plus a regex built from the pattern — `:id` becomes a capture group, `/users/42` matches, `42` lands in `req.params.id`, percent-encoding gets decoded. That is the whole mystery. **Middleware** is an array of functions taking `(req, res, next)`: each one can finish the request early (write a status and *not* call `next` — the chain stops) or do its work and call `next()` to pass the request down the line. Logging, auth, body-parsing — all the same shape. When you finish this lesson you have not used a framework; you have *built the 30 lines frameworks package*, and the packaging will never read as magic again.

<Pitfall title="Forgetting next() silently drops the request">
	<p>
		A middleware that neither responds nor calls `next()` leaves the request hanging — no response, no error, the client times out. The bug is invisible in the logs because nothing failed. The discipline: every middleware branch either writes to `res` or calls `next()`. Same trap on the handler side: if a route matched but the handler awaits something that never settles, the client hangs — the router cannot save you there.
	</p>
</Pitfall>

## Thirty lines, two ideas

Run the demo file for this lesson:

```bash
node code/4-http-server-scratch/4-3-router-middleware/demo.js
```

It prints: `[1]` the route table working — `/health` matching exactly, `/users/42` extracting the param, `/users/a%20b` decoding to `a b`; `[2]` the middleware chain — a log line per request, auth rejecting a tokenless request with 401 (chain stopped early, handler never ran), the same route with a good token passing log → auth → handler; `[3]` the 404: `/nope` matched no row, and "no route matched" *is* the 404.
