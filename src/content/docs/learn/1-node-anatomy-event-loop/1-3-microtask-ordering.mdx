## What you will learn

Between every loop phase — and after every callback — Node drains two **microtask** queues before moving on: first the entire `process.nextTick` queue, then the entire **Promise** queue (V8's own microtasks, including `await` continuations). `setImmediate` and `setTimeout` are *not* microtasks; they wait in their phases. This lesson pins the three rules the demo proves: nextTick drains first and completely; once Promise callbacks start, the whole Promise queue drains even if nextTicks are queued mid-drain; and both queues empty before any phase runs.

<Pitfall title="nextTick starves I/O; Promise does not (as much)">
	<p>
		A recursive `process.nextTick` chain never yields — timers and I/O wait forever, silently: no warning, no crash, the process just hangs. A recursive Promise chain starves phases from the start too (a resolved-promise loop never lets the timeout run) — the real difference is that promise callbacks still interleave with *other* promise work while nextTick recursion starves even the Promise queue. Rule of thumb: in libraries use `queueMicrotask` or Promise; keep `nextTick` for the rare "run before I/O continues" cases, and never in a loop without a base case.
	</p>
</Pitfall>

## Three queues, one verdict each

Run the demo file for this lesson:

