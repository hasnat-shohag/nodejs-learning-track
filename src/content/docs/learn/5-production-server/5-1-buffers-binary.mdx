## What you will learn

A JS string is a sequence of *characters*; everything below the runtime — sockets, files, TLS, crypto — moves *bytes*. The Bangla string `'হাই'` is 3 characters but **9 UTF-8 bytes**: every character costs three bytes, and a `content-length` header, a file size, or a hash all count the 9, not the 3. **Buffer** is Node's bridge: a fixed-length byte array with encoding helpers, and — the part that explains its behavior — a **TypedArray** subclass, a `Uint8Array` view over an `ArrayBuffer`. That single fact gives you the whole gotcha list: `Buffer.from(arrayBuffer)` shares memory rather than copying (write through the `Uint8Array`, read through the `Buffer`); `subarray` is a zero-copy *alias*, so writing through the slice mutates the parent; and decoding is a *choice* — the same 9 bytes read as `utf8` give you the Bangla back, read as `latin1` give silent mojibake, and `hex` shows you what is actually on the wire. Wrong decodings never throw; they lie quietly.

<Pitfall title="allocUnsafe returns undefined contents — it is an optimization, not a default">
	<p>
		`Buffer.alloc(n)` is guaranteed zeroed. `Buffer.allocUnsafe(n)` hands you pooled memory whose contents are *undefined* — whatever was there, is there. Write every byte before you read any, or you can leak another request's data into a response. In the demo it came back zeroed — that is luck, not a promise. Use `alloc` unless profiling proved the allocation matters.
	</p>
</Pitfall>
