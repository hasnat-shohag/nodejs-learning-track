## What you will learn

Plain HTTP sends identity and content in the clear — anyone on the path reads and rewrites both. **TLS** fixes exactly that, in two moves: a *certificate* lets the server prove who it is, and a *handshake* lets both sides derive a shared secret whose bytes never cross the wire. After that, HTTP runs unchanged over the encrypted channel — same methods, same headers, same `IncomingMessage`/`ServerResponse` objects, which is why `https.createServer` is `http.createServer` plus a `key` and `cert` option. The demo makes the trust model visible: a client *without* your CA refuses the self-signed certificate before any HTTP happens — `DEPTH_ZERO_SELF_SIGNED_CERT` — and that refusal is the system *working*; identity is checked first, conversation second. The client that passes the CA option verifies the chain and speaks `TLSv1.3` in both directions. Production swaps the self-sign step for a real certificate authority (Let's Encrypt) — the server code does not change, only who vouches.

<Pitfall title="CN is not enough — the certificate must name the exact host you dial">
	<p>
		A cert with `CN=localhost` is *invalid* for `https://127.0.0.1`: the hostname check runs against the Subject Alternative Name list, and Node rejects with `ERR_TLS_CERT_ALTNAME_INVALID` even though the CN "matches-ish". The demo's openssl call carries `-addext subjectAltName=IP:127.0.0.1,DNS:localhost` for exactly this reason. Self-signing without SANs is the most common "but it works in curl" trap.
	</p>
</Pitfall>

## Identity first, then encrypted HTTP

Run the demo file for this lesson:

```bash
node code/5-production-server/5-4-tls-https/demo.js
```

It prints: `[1]` openssl producing a self-signed key + certificate pair with subject and SANs; `[2]` the server on it, and a client with no CA refused — self-signed means untrusted *by default*; `[3]` the client with the CA option connecting: status 200, protocol `TLSv1.3`, body flowing over the verified channel — next to the same content over plain http with no identity and no encryption.
