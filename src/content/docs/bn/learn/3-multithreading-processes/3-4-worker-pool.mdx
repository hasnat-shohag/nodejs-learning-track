## এই লেসনে যা শিখবেন

একটি `new Worker` মানে ~30 ms spawn আর একটি পুরো V8 heap — প্রতিবার। প্রতি জবে একটা করে spawn করলে এই খরচ আপনার ট্রাফিকের সাথে বাড়ে — ৮ জব, ৮ spawn, পিকে ৮টি সমান্তরাল heap। **worker pool** প্যাটার্নই সমাধান, আর এটা তিনটি আইডিয়া: নির্দিষ্ট সংখ্যক worker একবার spawn; কাজ spawn নয়, মেসেজে বিতরণ; আর একটি কিউ যাতে বার্স্ট অপেক্ষা করে, spawn-storm নয়। যা কেনেন তা সাধারণত wall-clock নয় — মাল্টি-কোর মেশিনে one-shot worker পাল্লা দিতে পারে — কেনেন *boundedness*: কত জবই আসুক spawn আর peak worker স্থির। সাইজিংয়ে সাধারণ ক্ষেত্রের rule of thumb: CPU-bound কাজে pool = CPU cores, কারণ cores-এর বাইরে জবগুলো শুধু একে অপরের লাইনে পড়ে।

## সময় নয়, গণনা

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/3-multithreading-processes/3-4-worker-pool/demo.js
```

ছাপে: `[1]` spawn-per-job — ৮ spawn, পিকে ৮ সমান্তরাল worker, spawn খরচ ৮ বার; `[2]` একই ৮ জবে ৪-এর pool — ৪ spawn, প্রতি worker ২টি জব চালায় (`threadId` গণনায় প্রমাণ), reuse চোখে দেখা; `[3]` একই pool-এ ২০-জবের বার্স্ট — spawn আর পিক ৪-এই স্থির যতক্ষণ কিউ 16 → 0 ড্রেন করে, কিছু হারায়নি, spawn-storm নেই। wall-clock লাইনটা সৎভাবে পড়ুন: বড় মেশিনে [1] [2]-কে টেকে দিতে পারে; গণনাই বিশ্বাস করুন।
