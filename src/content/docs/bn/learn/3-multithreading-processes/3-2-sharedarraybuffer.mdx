## এই লেসনে যা শিখবেন

`postMessage` কপি করে; মাঝে মাঝে চাই দুই থ্রেড *একই* বাইটে — প্রসেস হচ্ছে একটি ইমেজ, একটি শেয়ার্ড কাউন্টার, একটি রিং বাফার। **SharedArrayBuffer** (SAB) ঠিক সেটাই: দুই আইসোলেট যে মেমরি ম্যাপ করতে পারে, কোনো পাশেই কপি নেই। কিন্তু শেয়ার্ড বাইট ভাঙে সেই একক-থ্রেড অনুমান যার ওপর JS দাঁড়িয়ে। `view[0] += 1` আসলে তিনটি অপারেশন — load, add, store — আর একই সেলে দুই থ্রেড চালালে দুজনেই একই পুরনো মান load করতে পারে, দুজনেই add, দুজনেই store, আর একটি ইনক্রিমেন্ট মিলিয়ে যায়। এটাই **data race**, বিরল তত্ত্ব নয়: ৩ কোটি + ৫০ লাখ ইনক্রিমেন্টের লোডে এই লেসনের ডেমো কয়েক মিলিয়ন আপডেট হারায়। সমাধান **Atomics**: `Atomics.add(view, 0, 1)` একটি অবিভাজ্য অপারেশন — প্রতিটি ইনক্রিমেন্ট জায়গা পায়। `Atomics.wait` / `Atomics.notify` টুলবক্স পূর্ণ করে: থ্রেডকে OS লেভেলে ঘুম পাতায়, CPU স্পিন ছাড়াই, আর ওপাশ থেকে জাগায়।

## রেস হারান, তারপর জেতান

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/3-multithreading-processes/3-2-sharedarraybuffer/demo.js
```

ছাপে: `[1]` রেস — দুই পাশ থেকে খাঁটি `view[0] += 1`-এ ফল আসে প্রত্যাশিত ৩.৫ কোটির অনেক নিচে; `[2]` একই লোডে দুই পাশেই `Atomics.add` — ঠিক ৩.৫ কোটি, প্রতিটি ইনক্রিমেন্ট হিসাবে আছে; `[3]` `Atomics.wait` main থ্রেডকে OS লেভেলে পার্ক করে রাখে worker-এর `Atomics.notify` না ডাকা পর্যন্ত — স্পিন ছাড়া ঘুম, জাগার ফাঁকে মাপা।
