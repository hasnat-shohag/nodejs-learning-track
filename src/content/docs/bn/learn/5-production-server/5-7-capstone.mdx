## এই লেসনে যা শিখবেন

প্রতিটা টুকরা এমন লেসন যা আপনি পেয়েছেন; capstone এক প্রসেসে সব জুড়ে দেয়। **Route**: `/` serve করে **ETag** স্ট্যাম্প করা body, `If-None-Match`-এর উত্তর 304 — caching চুক্তি; `/file/*` চালায় resolve-plus-startsWith **traversal guard**, filesystem ছোঁয়ার আগেই, আর `/file/../../etc/passwd` মরে 403-এ; `/hash` হলো CPU কাজ, আর এর *ভুল* ঠিকানা event loop — তাই এটা round-robin হয়ে যায় দুই-worker **thread pool**-এ (3-4-এর pool), প্রতিটা hash worker-এ ~৫০ms, আর main thread-এর ২০ms ticker টিকটিক চালায় — ফাঁক ২১ms। প্রতিটা reply বহন করে 5-5-এর চারটার মধ্যে তিনটি **security header** — টেবিলের উপর এক লুপ (capstone CSP ফেলে দেয়; আসল deployment-এ চারটাই থাকে)। Pool-এর reply route হয় job id দিয়ে, একটা শেয়ার্ড `message` listener আর pending-jobs Map-এর মধ্য দিয়ে: request-প্রতি `once('message')` হলো capstone-এর বানানো bug — কারণ একই worker-এ দুই job পড়লে দুই অপেক্ষাই প্রথম reply শোনে। আর shutdown ফিচার, শেষ কথা নয়: `server.close()` শোনা বন্ধ করে, `worker.terminate()` pool খালি করে, আর প্রসেস পরিষ্কার exit করে কারণ কোনো handle বাকি নেই — graceful redeploy-এরও একই শৃঙ্খলা।

## পুরো domain, এক প্রসেস

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/5-production-server/5-7-capstone/demo.js
```

ছাপে: `[1]` boot — pool worker উঠেছে, server শুনছে, header চালু; `[2]` static route — etag সহ 200, সেটা নিয়ে re-GET, 304 আর শূন্য body byte; `[3]` traversal চেষ্টা guard-এ 403; `[4]` চারটা concurrent `/hash` request pool-এর threadId-এ ছড়িয়ে, main-loop ticker এখনো ২০ms ফাঁকে — CPU কাজ loop-কে কখনো আটকায়নি; `[5]` shutdown — প্রসেস খোলা রাখার কিছুই বাকি নেই।
