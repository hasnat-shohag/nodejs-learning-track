## এই লেসনে যা শিখবেন

Caching আপনার সার্ভার আর browser-এর চুক্তি, header-এ স্বাক্ষরিত। **ETag** হলো *body-র* স্ট্যাম্প — এখানে তার SHA-256-এর প্রথম ১৬ hex char — আর browser-এর চুক্তির অর্ধেক হলো নীতি বললে সেটা `If-None-Match` হয়ে ফেরত পাঠানো। স্ট্যাম্প মিললে উত্তর দিন **304 Not Modified**, *শূন্য* body byte; browser নিজের cached কপি পুনর্ব্যবহার করে, wire দাম দেয় শুধু header-এর। ফাইল বদলালে নতুন body hash আলাদা, স্ট্যাম্প সরে, client পায় পুরো 200 ফ্রেশ byte সহ — ডেমো দুই দিকই দেখায়: ফাইল overwrite করার *আগে* পুরনো ETag ধরে রেখে। **Cache-Control** বলে নীতি: `public, max-age=60` — এক মিনিট না জিজ্ঞেস করে কপি পুনর্ব্যবহার করতে পারে; `no-cache` — প্রতিবার revalidate; `no-store` — জমানোই নিষেধ। মনে রাখার এক লাইন: ETag বলে body *কী*, Cache-Control বলে কপি *কতক্ষণ বিশ্বাস্য* — একটা ছাড়া আরেকটা অকেজো।

## স্ট্যাম্প, নীতি, আর ফ্রি 304

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/5-production-server/5-3-static-server-caching/demo.js
```

ছাপে: `[1]` প্রথম GET — extension অনুযায়ী content-type, reply-তে `etag` আর `cache-control`; `[2]` `If-None-Match` নিয়ে re-GET — 304, body byte: 0; `[3]` request-এর মাঝে ফাইল নতুন লেখা — পুরনো স্ট্যাম্প পাঠানো, নতুন body ফেরত, 200, আর ETag content-এর সাথে সরে গেছে।
