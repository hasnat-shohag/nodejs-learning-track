## এই লেসনে যা শিখবেন

আপনার handler যে request object পায় সেটা *নিজেই* একটা Readable stream, আর upload-এ বিশেষ কিছু নেই: সময়ের সাথে বাইট আসছে। Streaming সার্ভার প্রতিটি `'data'` chunk পাঠায় `createWriteStream`-এ — chunk থেকে disk, কখনোই chunk থেকে RAM থেকে disk নয় — আর এর heap থাকে সমতল (~7MB আগে, ~7.6MB চলার সময়) যখন ২০MB upload নামে, আর দুটো ২০MB upload interleave করলেও ততটাই সমতল। Naive সার্ভার প্রতিটি chunk array-তে জমায়, `'end'`-এ `Buffer.concat` করে — একসাথে পুরো ২০,৯৭১,৫২০ byte মেমরিতে ধরে রাখে; concurrent upload দিয়ে গুণ করলে সেটাই রাত ৩টার OOM। **Multipart upload** — browser যেটা পাঠায় `<input type="file">`-এর জন্য — গঠনে কিছু বদলায় না: body এমন একটা Readable যার byte-এ boundary marker বসে, তাই *streaming করতে করতে* boundary-তে কেটে নিতে হয়। বাস্তবের নিয়ম হলো boundedness: সর্বোচ্চ body সাইজ ঠিক করুন, আগেই reject করুন — কারণ "stream করো" মানেই চলে না "client আমাকে যা খুশি পাঠাক"।

## Chunk থেকে disk, কখনো chunk থেকে RAM নয়

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/5-production-server/5-2-streaming-uploads/demo.js
```

ছাপে: `[1]` ২০MB upload 64KB slice-এ disk-এ নামছে — আগে/চলার heap প্রমাণ করে body কখনোই RAM-এ ছিল না; `[2]` দুটো একসাথে, chunk interleave করেও heap সমতল; `[3]` anti-pattern — একই upload পুরোটা মেমরিতে, একসাথে ২০MB — যে সংখ্যাটা আপনার container limit পড়ে।
