## এই লেসনে যা শিখবেন

Error আপনার server-এ পৌঁছায় দুই চ্যানেলে, দুটোর জন্যই জাল লাগবে। **Sync** throw handler-এর ভেতরে catch করা যায়: handler body-কে `try/catch`-এ মুড়ুন, 500 পাঠান, stack log করুন, সার্ভার চালু রাখুন। **Async** ব্যর্থতা — rejected promise, stream-এর `error` ইভেন্ট — `try/catch`-এর চোখেই পড়ে না; শুধু `.catch()` (বা `async handler` + `.catch` র‍্যাপার) দেখে। আর ঝুঁকিটা আসল: Node 15 থেকে **unhandled rejection ডিফল্টে প্রসেস মারে** — এক route-এ একটা `.catch` না থাকলে পুরো server নিচে। ডেমো দেখায় দুই জালই আর প্রসেস-লেভেল শেষ উপায়: `process.on('uncaughtException')` ফায়ার করে, কিন্তু তখন প্রসেসের অবস্থা অজানা — handler-টা *logging আর পরিষ্কার exit-এর* জন্য, সার্ভার চালিয়ে যাওয়ার জন্য নয়। Node-এর fs/net/crypto জুড়ে থাকা error-first callback রীতি (`(err, result) => ...`) তৃতীয় জাল, আর 404 বনাম 500 নিয়ম — অজানা route মানে ক্লায়েন্টের সমস্যা, handler-এর throw মানে আপনার — ক্লায়েন্টকে অর্থ পাঠায়, log-কে stack।

## দুই জাল আর এক শেষ-উপায়

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/4-http-server-scratch/4-4-error-handling/demo.js
```

ছাপে: `[1]` sync throw `try/catch`-এ ধরা, 500 গেছে, প্রসেস বেঁচে; `[2]` একই async rejection `.catch`-এ ধরা (500 গেছে) — তারপর `.catch` *ছাড়া* একই rejection child প্রসেসে: exit 1, প্রসেস মরল, কারণ unhandled rejection ডিফল্টেই Node মারে; `[3]` child-এ `uncaughtException`: handler log করে, exit-এর যুক্তি ছাপে, ইচ্ছাকৃতভাবে বেরায় — শেষ-উপায় ঠিক শেষ-উপায়ের মতোই।
