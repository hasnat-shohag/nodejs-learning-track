## এই লেসনে যা শিখবেন

`http.createServer(handler)`-এর দাম শূন্য — একটি অবজেক্ট বানিয়ে ফেরায়। Server আসল হয় `.listen()`-এ: Node socket বানিয়ে bind করে, kernel পোর্ট বরাদ্দ দেয়, আর `'listening'` ইভেন্ট ফায়ার করে — `server.address()`-এ ঠিকানা। তারপর দুই ইভেন্ট লেয়ার চলে: `'connection'` দেয় খাঁটি একটি `net.Socket` (TCP লেয়ার), আর প্রতিটি socket-এর ওপর `'request'` বসে **parsed** HTTP হয়ে — একটি **IncomingMessage** (method, url, headers, আর body হিসেবে readable stream) আর একটি **ServerResponse** (writable stream সাথে `writeHead`/`end`)। লেয়ারিংটাই performance-এর গল্পও: HTTP/1.1 keep-alive মানে একটি TCP connection অনেক request বয়ে আনে, তাই দামি অংশটা (connection setup) খরচ একবারই, ভাগ হয়ে যায়। ডেমোর তিন request এক connection-এই চলে — `connection` একবারই ফায়ার করে।

## এক server, দুই ইভেন্ট লেয়ার

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/4-http-server-scratch/4-1-server-lifecycle/demo.js
```

ছাপে: `[1]` `createServer()` ফিরেছে আর `listening === false` — `.listen()` ছাড়া কিছুই হয় না; `[2]` `'listening'` ইভেন্ট, kernel-দেওয়া পোর্টসহ; `[3]` একটি `POST /hello?x=1`-এর জন্য handler সত্যিই যা পায় — method, url, HTTP version, সব আগেই parsed; `[4]` তিনটি request একটিই TCP connection-এ — keep-alive handshake-এর খরচ ভাগ করছে।
