## এই লেসনে যা শিখবেন

`http.createServer(handler)`-এর দাম শূন্য — একটি অবজেক্ট বানিয়ে ফেরায়। Server আসল হয় `.listen()`-এ: Node bind করে, kernel socket বরাদ্দ করে, আর `'listening'` ইভেন্ট ফায়ার করে — `server.address()`-এ ঠিকানা। তারপর দুই ইভেন্ট লেয়ার চলে: `'connection'` দেয় খোলা একটি `net.Socket` (TCP লেয়ার), আর `'request'` বসে প্রতিটি socket-এর ওপর **parsed** HTTP হয়ে — একটি **IncomingMessage** (method, url, headers, আর body হিসেবে readable stream) আর একটি **ServerResponse** (writable stream সাথে `writeHead`/`end`)। লেয়ারিংটাই performance-এর গল্পও: HTTP/1.1 keep-alive মানে একটি TCP connection অনেক request বয়ে আনে, তাই দামি অংশটা (connection setup) একবার দেওয়া, ভাগ করে খরচ। ডেমোর তিন request এক connection-এই চলে — `connection` একবারই ফায়ার করে।

	<p>
		`server.close()` *নতুন* connection বন্ধ করে কিন্তু চালু keep-alive socket খোলাই থাকে, তাই যে স্ক্রিপ্ট `close()` ডেকে callback-এর জন্য অপেক্ষা করে সে চিরদিন ঝুলে থাকতে পারে — idle ক্লায়েন্ট socket ধরে রেখেছে। সমাধান `server.closeAllConnections()` (Node 18.2+), নাহলে ক্লায়েন্ট পাশ থেকে বন্ধ করুন। একই পরিবার: পোর্ট `0` দিয়ে `server.listen(port)` করলে kernel বরাদ্দ দেয় — আসল পোর্ট `'listening'` callback-এ `server.address().port` থেকে পড়ুন, অনুমান কখনো নয়।
	</p>

## এক server, দুই ইভেন্ট লেয়ার

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/4-http-server-scratch/4-1-server-lifecycle/demo.js
```

ছাপে: `[1]` `createServer()` ফিরেছে আর `listening === false` — `.listen()` ছাড়া কিছুই হয় না; `[2]` `'listening'` ইভেন্ট, kernel-দেওয়া পোর্টসহ; `[3]` একটি `POST /hello?x=1`-এর জন্য handler সত্যিই যা পায় — method, url, HTTP version, সব আগেই parsed; `[4]` তিনটি request একটিই TCP connection-এ — keep-alive handshake-এর খরচ ভাগ করছে।
