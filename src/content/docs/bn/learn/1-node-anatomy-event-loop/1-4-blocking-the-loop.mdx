## এই লেসনে যা শিখবেন

এক লাইনের হট-লুপ JavaScript একসাথে সব কানেক্টেড ক্লায়েন্টের সার্ভার আটকে দিতে পারে — কারণ যে থ্রেড ব্লক হলো, আপনার callback চলে সেই **একমাত্র** থ্রেডেই। কস্ট মডেল সরল: **lag একবার, সম্পূর্ণভাবে, প্রতিটি ঝুলন্ত callback-ই দেয়**। এই লেসন সেটি দৃশ্যমান করে একটি প্রোব দিয়ে: ৫০ms ইন্টারভাল পিং, যার গ্যাপ বাড়ে ব্লক-সময়ে (সাথে ব্লক শুরুর মুহূর্তে ইন্টারভালের যতটুকু পার হয়ে গিয়েছিল) — পাশে একই ২০০ms CPU কাজ `setImmediate` দিয়ে স্লাইস করা, যেখানে কোনো গ্যাপই বাড়ে না।

## প্রোব: ৫০ms পিং কখনো মিথ্যা বলে না

এই লেসনের ডেমো ফাইলটি চালান:

```bash
node code/1-node-anatomy-event-loop/1-4-blocking-the-loop/demo.js
```

প্রোব প্রতি ৫০ms ফায়ার করে প্রতিটি গ্যাপ রেকর্ড করে। ২০০ms সিনক্রোনাস স্পিন একটি প্রোব উইন্ডোর ভেতরে পড়ে: সেই গ্যাপ ছাপে ~২১০ — ব্লক-সময় সাথে স্পিন শুরুর মুহূর্তে ইন্টারভালের বাকি অংশ। তারপর ডেমো একই ২০০ms কাজ ৫ms স্লাইসে `setImmediate` রি-আর্ম করে চালায় — প্রতিটি গ্যাপ ~৫০-ই থাকে। কাজ এক, ওয়াল-টাইম এক; কিন্তু সার্ভার রেসপন্সিভ রাখল দুটোর একটাই।
