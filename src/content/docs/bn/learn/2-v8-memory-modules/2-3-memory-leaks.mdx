## এই লেসনে যা শিখবেন

GC যা পৌঁছাতে পারে তা মুক্ত করতে পারে না, আর পুরো খেলাটাই "পৌঁছানো"। Node-এর প্রায় প্রতিটি লিকে পৌঁছানো আঁকে ধরে তিন রূপে: মডিউল স্টেটে আটকে থাকা একটি **ক্লোজার** (এমন রিকোয়েস্ট Map যা কেউ ছাঁটে না), নিজের স্কোপ বাঁচিয়ে রাখা একটি **টাইমার**, আর কখনো না-সরানো একটি **লিসেনার** — ১১তমতে Node নিজেই সতর্ক করে। এই লেসন প্রথম আর তৃতীয়টা বানায়, GC-জোর করে মেপে দেখায় কোন স্ট্রাকচার লিক আর কোনটা সীমিত, আর একটি **heap snapshot** লেখে যা DevTools-এ খুলে retainer edge-টা নিজেই দেখা যায়।

## লিক বানান, তারপর সীমিত করুন

এই লেসনের ডেমো ফাইলটি চালান (ফ্ল্যাগটি খেয়াল করুন):

```bash
node --expose-gc code/2-v8-memory-modules/2-3-memory-leaks/demo.js
```

`[1]` ৪০টি পেলোড মডিউল-লেভেল Map-এ আটকে রাখে: GC চলে আর heap <em>বাড়াই</em> থাকে — ৪০টি পৌঁছানো-যোগ্য, লিক নিশ্চিত। `[2]` একই লোড চালায় ১০-এন্ট্রির eviction-ওয়ালা ক্যাশে: ৪০০ রিকোয়েস্ট পরে heap বেসলাইনে ফেরে, কারণ map নিজেই সীমিত। `[3]` ১২টি লিসেনার যোগ করে Node-এর নিজের `MaxListenersExceededWarning`-কে stderr-এ ডেকে আনে। `[4]` একটি `.heapsnapshot` লেখে `/tmp`-তে — Chrome DevTools-এর Memory প্যানেলে খুললে লিক করা Map তার retainer চেইনসহ দেখা যায়, আর ওই চেইনই সেই edge যা আপনাকে ভাঙতে হবে।
